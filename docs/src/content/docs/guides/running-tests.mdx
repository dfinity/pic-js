## Configuring the server binary

By default, the PocketIC server binary downloaded by the `@dfinity/pic` install script is used, which requires [allowing the install script](./getting-started#allowing-the-install-script). A different binary can be provided using the `binPath` option, for example:

```ts
const picServer = await PocketIcServer.start({
  binPath: '/path/to/pocket-ic',
});
```

Alternatively, the `POCKET_IC_BIN` environment variable can be set to the path of the binary, for example:

```shell
POCKET_IC_BIN=/path/to/pocket-ic npm test
```

The `binPath` option takes precedence over the `POCKET_IC_BIN` environment variable.

## Configuring logging

### Canister logs

Logs for canisters can be configured when running the PocketIC server using the `showCanisterLogs` option, for example:

```ts
const picServer = await PocketIcServer.start({
  showCanisterLogs: true,
});
```

To assert on a canister's logs in a test, fetch its log records with `fetchCanisterLogs`. By default, only the canister's controllers can read its logs; other principals need the canister's [log visibility](https://docs.internetcomputer.org/guides/canister-management/settings/#log-visibility) to allow them:

```ts
const pic = await PocketIc.create(picServer.getUrl());
// set up a canister controlled by `controller`...

const logs = await pic.fetchCanisterLogs({
  canisterId,
  sender: controller.getPrincipal(),
});
const messages = logs.map(log => new TextDecoder().decode(log.content));
```

Records can be narrowed to an index or timestamp range with `filter`, for example `filter: { type: 'byIdx', start: 0n, end: 10n }`.

### Server logs

Logs for the PocketIC server can be configured by setting the `POCKET_IC_LOG_DIR` and `POCKET_IC_LOG_DIR_LEVELS` environment variables.

The `POCKET_IC_LOG_DIR` variable specifies the directory where the logs will be stored. It accepts any valid relative, or absolute directory path.

The `POCKET_IC_LOG_DIR_LEVELS` variable specifies the log levels. It accepts any of the following `string` values: `trace`, `debug`, `info`, `warn`, or `error`.

For example:

```shell
POCKET_IC_LOG_DIR=./logs POCKET_IC_LOG_DIR_LEVELS=trace npm test
```

It's also possible to set individual log levels for different modules, for examples:

```shell
POCKET_IC_LOG_DIR=./logs POCKET_IC_LOG_DIR_LEVELS=pocket_ic_server=trace,tower_http=info,axum::rejection=info npm test
```

### Runtime logs

Logs for the IC runtime can be configured when running the PocketIC server using the `showRuntimeLogs` option, for example:

```ts
const picServer = await PocketIcServer.start({
  showRuntimeLogs: true,
});
```

## Testing interleaved calls

A canister can process other calls while one of its calls waits at an `await`, which can cause reentrancy bugs. To reproduce this, submit the calls with a deferred actor before awaiting any of them. They are executed together, so the second call runs while the first one waits:

```ts
const actor = pic.createDeferredActor<_SERVICE>({ idlFactory, canisterId });

const first = await actor.withdraw(amount);
const second = await actor.withdraw(amount);

await first();
await second();
```

`pic.submitCall` does the same for calls with a Candid-encoded argument, and `pic.ingressStatus` checks whether a submitted call has finished.

## Live mode

`makeLive` makes the instance execute rounds on its own, in real time, and starts an HTTP gateway, so agents can call canisters as they would on a real network:

```ts
const gatewayPort = await pic.makeLive();
const agent = await HttpAgent.create({
  host: `http://localhost:${gatewayPort}`,
  shouldFetchRootKey: true,
});

// make calls with the agent...

await pic.stopLive();
```

The gateway can be configured with the `httpGateway` option, for example `pic.makeLive({ httpGateway: { port: 8080 } })`.

To give a test more time between rounds, set a minimum delay between them with `artificialDelayMs`, for example `pic.makeLive({ artificialDelayMs: 500 })`. This delays calls that wait for rounds, i.e. calls made through the HTTP gateway or with `pic.submitCall`. Calls made with an actor or `pic.updateCall` execute their rounds themselves and are not delayed.
